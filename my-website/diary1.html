💣 记一次浮动清除的血泪史

📅 2026年7月28日 · 阅读约 3 分钟

刚学 CSS 布局的时候，我天真地以为 float: left 是个万能神器。 直到我写出了下面这段 "完美" 的代码……

<!-- 我梦想中的两栏布局 --> <div class="container"> <div class="left">左边内容</div> <div class="right">右边内容</div> </div>
/* CSS */ .left { float: left; width: 70%; } .right { float: right; width: 30%; } .container { background: #f0f0f0; /* 背景色消失了！😱 */ }

结果刷新页面一看——父容器的背景色完全消失了！整个容器高度变成了 0！ 我当时整个人都懵了，明明写了背景色，为什么就是不显示？

🔍 问题根源

浮动元素会脱离文档流，父容器感知不到子元素的高度，自然就塌陷了。 这就好比你明明往书包里塞了书，但书包却说自己"空无一物"一样离谱。

⚠️ 核心知识点： 浮动元素不占据文档流空间，父容器默认高度为 0，必须主动清除浮动（Clearfix）。

💊 三种解决方案

方案一：父容器加 overflow: hidden

.container { overflow: hidden; /* 最简单的方案 */ }

方案二：空 div 清除浮动（不推荐，语义垃圾）

<div style="clear:both;"></div>

方案三：伪元素 Clearfix（最优雅，面试加分项）

.container::after { content: ""; display: block; clear: both; }
✅ 最终结论： 现在做布局，我优先用 Flexbox 或 Grid，尽量避开 float。 如果非得用，那就老老实实加 ::after 伪元素清除浮动，干净又体面。

这次踩坑教会我一个道理：不懂原理的 "能用就行" 迟早要还的。 后来我把所有 float 布局都改成了 Flex，整个代码瞬间清爽了 10 倍。
