🎨 背景图失踪迷案

📅 2026年7月20日 · 阅读约 2 分钟

那是一个普通的下午，我决定给自己的网页加一张炫酷的背景图。 我自信满满地写下了这行代码：

body { background-image: url(风景图.jpg); background-size: cover; }

然后刷新页面——一片空白。

我心想：是不是路径写错了？于是改成 url(./风景图.jpg)，再刷新——还是空白。

接下来半小时，我试了各种路径：

url(风景图.jpg) ❌ url(./风景图.jpg) ❌ url(/风景图.jpg) ❌ url(../风景图.jpg) ❌ url(images/风景图.jpg) ❌

正当我准备砸电脑的时候，F12 开发者工具救了我。 控制台里清清楚楚地显示着：

🚨 404 Not Found: 风景图.jpg
—— 文件明明在文件夹里，怎么就 404 了呢？

我盯着文件名看了半天，突然灵光一闪：这文件是中文名啊！

虽然现代浏览器对中文 URL 的支持越来越好，但某些服务器环境下，中文文件名还是会被编码解析成乱码，导致路径匹配失败。 而且更坑的是，如果图片是从微信或 QQ 保存的，文件名可能是 IMG_2026_风景图.jpg 这种混合编码，直接爆雷。

✅ 血的教训： 图片文件永远用英文 + 数字 + 下划线命名！ 比如 scenery.jpg 或 bg_cover.png，千万别用中文或特殊符号。

改完文件名后，一行代码都没动，图片就出来了：

/* 改名后秒出图 🎉 */ body { background-image: url(scenery.jpg); background-size: cover; }

从此以后，我所有的图片文件都规规矩矩用英文命名，再也没踩过这个坑。 这次经历让我记住了：前端无小事，一个空格、一个中文名都可能让你怀疑人生。
